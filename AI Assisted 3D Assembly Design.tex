\section*{Abstract}

Engineering CAD assemblies consist of multiple interconnected components whose correct selection is time-consuming and expertise-dependent. Modern CAD tools such as SolidWorks, CATIA, and Fusion 360 provide no contextual intelligence during assembly creation, forcing engineers to rely entirely on domain knowledge to choose and position components. This project addresses this gap by training a \textbf{Graph Attention Network (GAT)} on assembly graphs derived from STEP files to detect \textbf{missing components} via link prediction.

Each CAD assembly is converted into an attributed graph using gmsh with the OpenCASCADE kernel: solid bodies become nodes (22-dimensional feature vectors including geometry-driven component type, SDF statistics, and affine-invariant shape descriptors) and physical contacts between bodies become edges (6-dimensional features encoding mate type and joint type). A 3-layer GAT encoder produces 64-dimensional node embeddings, which are fed to a Link Predictor MLP that scores candidate edges to identify missing component connections.

The system incorporates three complementary analysis modules: (1) the GNN-based link predictor for missing connection detection, (2) an \textbf{Assembly Completeness Model} (\texttt{AssemblyTemplateDB}) that learns per-category component-type distributions from training data to identify what components are missing, and (3) an \textbf{Octree-based Open Surface Detector} (inspired by the spatial partitioning technique in Borah \& Borah, 2020) that identifies the precise mesh surfaces where missing components should be assembled. A \textbf{Gemini-powered Skills AI agent} (AIDA) explains predictions in engineering language.

Trained on 1,760 assembly graphs (643 from the Fusion 360 Gallery dataset and 137 curated local assemblies, after deduplication and quality filtering), the model achieves a mean AUC-ROC of $0.625 \pm 0.017$ and a mean Average Precision of $0.878 \pm 0.005$ under 5-fold cross-validation --- the most stable model across folds to date. The solution is implemented entirely in Python using PyTorch Geometric, without dependency on proprietary CAD software APIs, and is deployed as an interactive Streamlit application with real-time 3D visualisation.

\chapter{Introduction}
%=============================================================================

Computer-Aided Design (CAD) is the cornerstone of modern engineering, enabling the creation, modification, and optimisation of designs in a digital environment. CAD assemblies --- collections of multiple interconnected mechanical components --- are central to industries ranging from automotive to aerospace, consumer electronics, and industrial machinery. The process of assembling components in a CAD environment requires selecting the right parts, positioning them correctly, and defining the appropriate mate constraints (coincident, concentric, tangent, etc.) between them.

Despite decades of CAD tool evolution, the assembly process remains fundamentally manual and expertise-dependent. Engineers rely on years of accumulated domain knowledge to identify which components belong in an assembly, detect when parts are missing, and determine the correct assembly sequence. This creates significant challenges: junior engineers face steep learning curves, inconsistent choices arise between designers working on equivalent subassemblies, and partially defined assemblies have no mechanism to detect or fill missing parts.

This project explores the application of \textbf{Graph Neural Networks (GNNs)} to the problem of intelligent assembly assistance. By representing CAD assemblies as graphs --- where solid bodies are nodes and physical contacts between bodies are edges --- the problem of detecting missing components naturally maps to \textbf{link prediction}: identifying edges (connections) that should exist but are absent in the current assembly state.

\section{Problem Statement}

Modern CAD tools (SolidWorks, CATIA, Fusion 360) offer no contextual intelligence during assembly creation. Engineers rely entirely on domain knowledge to choose and position each component. The key pain points are:

\begin{enumerate}[label=\arabic*.]
    \item \textbf{Knowledge barrier:} Junior engineers lack the assembly patterns that experienced designers have built over years of practice.
    \item \textbf{No automation:} Existing CAD tools offer no intelligent part suggestion or missing component detection during assembly creation.
    \item \textbf{Non-standardisation:} Different designers make inconsistent choices for equivalent subassemblies, leading to quality and maintenance issues.
    \item \textbf{Incomplete assemblies:} Partially defined assemblies have no mechanism to detect or fill missing parts automatically.
\end{enumerate}

\textbf{Research gap:} No existing system applies graph-based deep learning to recommend components from partial CAD assembly graphs without dependency on proprietary CAD APIs.

\section{Objectives}

The primary objectives of this project are:

\begin{enumerate}[label=\arabic*.]
    \item \textbf{Graph construction pipeline:} Develop a robust pipeline to convert STEP files into attributed assembly graphs using gmsh (OpenCASCADE) with geometry-enriched node features (22-dimensional) and edge features (6-dimensional).
    \item \textbf{Missing component detection:} Train a Graph Attention Network (GAT) with a Link Predictor to detect missing connections in partial assemblies, targeting AUC-ROC $\geq 0.85$ and Average Precision $\geq 0.82$.
    \item \textbf{Assembly completeness model:} Build a template-based system that learns per-category component-type distributions to identify what types of components are missing from a partial assembly.
    \item \textbf{Open surface detection:} Implement an Octree-based spatial analyser to identify the precise physical surfaces where missing components should be attached.
    \item \textbf{AI-powered explanation:} Integrate a Gemini-based Skills AI agent to translate GNN predictions into actionable engineering language.
    \item \textbf{Interactive deployment:} Deploy the system as a Streamlit web application with real-time 3D visualisation, inference, and explanation capabilities.
\end{enumerate}

\section{Scope of the Project}

The project is divided into two phases:

\begin{itemize}
    \item \textbf{Phase 1 (May -- July 2026):} Base replication --- missing component detection via GAT link prediction, assembly completeness model, open surface detection, AIDA Skills AI, and Streamlit deployment. Evaluation metrics: AUC-ROC and Average Precision.

The system operates on standard STEP/STP files (ISO 10303) and does not require proprietary CAD software APIs, making it universally applicable across CAD platforms.

\chapter{Literature Survey}
%=============================================================================

This chapter reviews the existing research and methodologies relevant to the project, spanning graph neural networks, B-Rep generative models, CAD representation learning, and spatial mesh analysis. The survey identifies the research gaps that this project aims to address.

\section{Existing Systems}

\subsection{Graph Neural Networks for Link Prediction}

\textbf{Kipf \& Welling (2017)} introduced the Graph Convolutional Network (GCN), which applies spectral convolutions on graph-structured data by aggregating neighbour features through a normalised adjacency matrix. GCN demonstrated strong performance on node classification and link prediction benchmarks but treats all neighbours equally, lacking an attention mechanism to weight the importance of different connections.

\textbf{Veli\v{c}kovi\'{c} et al. (2018)} proposed the Graph Attention Network (GAT), which introduces learnable attention coefficients to the neighbourhood aggregation step. Multi-head attention allows the model to attend to different structural patterns simultaneously. GAT has shown superior performance over GCN on heterogeneous graphs where neighbour importance varies, making it particularly suitable for assembly graphs where different mate types carry different structural significance.

\textbf{Hamilton, Ying \& Leskovec (2017)} introduced GraphSAGE (SAmple and agGREgate), which learns node embeddings by sampling and aggregating features from a node's local neighbourhood. GraphSAGE supports inductive learning on unseen nodes, which is relevant for inference on new assemblies not seen during training.

\textbf{``Can GNNs Learn Link Heuristics?'' (2024)} investigates whether GNNs can learn common link prediction heuristics such as common neighbours, Jaccard coefficient, and Adamic-Adar index directly from graph structure. The paper demonstrates that while GNNs can approximate these heuristics, explicit structural features can complement learned representations for improved link prediction.

\subsection{B-Rep Generative Models and CAD Synthesis}

\textbf{Du et al. (2024) -- BrepGen} introduced a B-Rep generative diffusion model with structured latent geometry. BrepGen generates boundary representation (B-Rep) solids by learning latent codes for faces, edges, and vertices, then decoding them into valid CAD geometry. While focused on single-part generation rather than assembly analysis, BrepGen demonstrates that deep learning can capture the geometric structure of B-Rep models.

\textbf{Jayaraman et al. (2024) -- SolidGen} proposed an autoregressive model for direct B-Rep synthesis and editing. SolidGen generates CAD construction sequences step by step, enabling both creation and modification of solid models. The autoregressive approach is conceptually related to next-component prediction in assembly design, where each added component depends on the existing partial assembly.

\textbf{Wang et al. (2025) -- CAD-GPT} synthesises CAD construction sequences using spatial reasoning-enhanced multimodal LLMs. CAD-GPT combines language understanding with 3D spatial reasoning to generate CAD models from natural language descriptions. This work highlights the potential of AI-assisted CAD workflows but operates at the individual part level rather than the assembly level.

\subsection{Heterogeneous Graph Learning}

\textbf{``Heterogeneous Graph Contrastive Learning'' (2023)} proposes contrastive learning methods for heterogeneous graphs with multiple node and edge types. This is directly relevant to CAD assemblies where nodes represent different component types (body, fastener, bearing, shaft, plate, housing, gear) and edges represent different mate constraints (coincident, concentric, parallel, tangent, fixed). The project's Phase 2 plans to incorporate heterogeneous GNN typed embeddings building on these ideas.

\subsection{Assembly Analysis and Spatial Reasoning}

\textbf{Jones et al. (2021) -- ``Learning Bottom-up Assembly of Parametric CAD Joints''} addresses the problem of assembling parametric CAD parts by learning joint predictions. This work is the closest to the current project's objectives but relies on parametric CAD representations and proprietary joint annotations rather than the geometry-only approach adopted here.

\textbf{Koch et al. (2019) -- ABC Dataset} created a large-scale collection of over 1 million CAD models in STEP/B-Rep format, providing geometric metadata including bounding boxes, volume, and surface area. The ABC dataset serves as a foundational resource for geometric deep learning research on CAD models.

\textbf{Mo et al. (2019) -- PartNet} contributed a large-scale benchmark of 573,585 3D parts across 26 object categories with fine-grained, instance-level, and hierarchical part annotations. PartNet's hierarchical annotations inform the edge feature construction approach used in this project.

\textbf{Willis et al. (2021) -- Fusion 360 Gallery Dataset} released 8,251 assemblies with 154K bodies from the Autodesk Fusion 360 CAD platform. This project integrates 643 assembly STEP files from the Fusion 360 Gallery as the primary training dataset, representing the largest publicly available source of real-world CAD assemblies.

\subsection{Mesh Processing and Spatial Partitioning}

\textbf{Borah \& Borah (2020)} proposed a Prediction Error Expansion (PEE) based reversible polygon mesh watermarking scheme that uses Octree spatial partitioning for regional tamper localisation. In their approach, an Octree divides the mesh's bounding volume into independent spatial sub-blocks, and each block's vertices are authenticated separately to localise tampered regions. This spatial decomposition concept --- enabling localised, per-region decisions --- is directly adapted in this project for open surface detection, where the Octree partitions free-surface centroids to identify where missing components should be placed.

\textbf{Ying et al. (2019) -- GNNExplainer} introduced a model-agnostic approach for generating explanations of GNN predictions by identifying the important subgraph structures and node features. GNNExplainer is planned for Phase 2 integration to provide interpretable explanations of which graph structures drive the missing component predictions.

\section{Limitations of Existing Systems}

The reviewed literature reveals several key limitations:

\begin{enumerate}[label=\arabic*.]
    \item \textbf{Part-level focus:} Most generative CAD models (BrepGen, SolidGen, CAD-GPT) operate at the individual part level, not at the assembly level where component interactions matter.
    \item \textbf{Proprietary API dependency:} Systems like the Fusion 360 joint prediction work rely on proprietary CAD APIs for constraint metadata, limiting portability across CAD platforms.
    \item \textbf{No geometry-driven component typing:} Existing approaches typically require labelled component-type datasets rather than inferring types directly from geometric properties (SDF, shape descriptors).
    \item \textbf{No spatial localisation:} No existing system identifies the \textit{precise physical surfaces} where missing components should be placed; they only name what is missing.
    \item \textbf{No engineering-language explanation:} Predictions are presented as numerical scores without translation into actionable engineering recommendations.
\end{enumerate}

\section{Proposed Solution}

This project addresses the identified gaps through a multi-module system:

\begin{enumerate}[label=\arabic*.]
    \item A \textbf{geometry-only graph construction pipeline} that works on standard STEP files without proprietary APIs, using gmsh + OpenCASCADE for parsing, trimesh for exact surface area computation, and SDF ray-casting for component type inference.
    \item A \textbf{3-layer GAT with Link Predictor} for missing component detection via link prediction on assembly graphs.
    \item An \textbf{Assembly Completeness Model} that learns per-category component distributions from training data and identifies gaps in partial uploads.
    \item An \textbf{Octree-based Open Surface Detector} (adapted from Borah \& Borah, 2020) that localises the exact surfaces needing assembly.
    \item A \textbf{Gemini-powered Skills AI agent} (AIDA) that explains predictions in structured engineering language.
\end{enumerate}

\section{System Architecture}

The system follows a modular pipeline architecture with four stages: (1) STEP parsing and graph construction, (2) GNN-based link prediction, (3) assembly completeness and open surface analysis, and (4) AI-powered explanation and visualisation.

\begin{figure}[H]
\centering
\includegraphics[width=0.95\textwidth]{system_architecture.png}
\caption{System Architecture Diagram --- from STEP file input through graph construction, GNN inference, complementary analysis modules, to the Streamlit front-end with 3D viewer.}
\end{figure}

The architecture is summarised as:

\begin{verbatim}
STEP file --> gmsh (OpenCASCADE) --> PyG assembly graph
  Nodes (22-dim): type one-hot (8) + log-vol + log-SA
    + bbox dx/dy/dz + affine-invariant shape (5)
    + SDF mean + SDF var + SA/V + log-holes
  Edges (6-dim): mate-type encoded + weight
    + joint-type one-hot (4)

Assembly graph --> AssemblyGNN (3-layer GAT)
  --> node embeddings (64-dim)
  --> LinkPredictor (MLP) --> binary edge scores
  --> missing component detection (AUC-ROC, AP)

Parallel: AssemblyTemplateDB --> assembly type + missing
          OctreeNode --> open surface joints

Skills AI: Gemini 2.5 Flash --> AIDA explanations
All outputs --> Streamlit dual-panel UI
\end{verbatim}

\section{Graph Construction Pipeline}

The graph construction pipeline in \texttt{back\_end/dataset.py} converts each STEP file into an attributed PyG \texttt{Data} object using a three-tool approach:

\subsection{Step 1: STEP Parsing with gmsh + OpenCASCADE}

\begin{enumerate}
    \item Load the STEP file and synchronise the OpenCASCADE kernel.
    \item Perform \textbf{Boolean fragmentation} (\texttt{gmsh.model.occ.fragment()}) --- this forces physically touching bodies to share exact boundary surface tags, enabling contact detection.
    \item For each solid body: extract volume (\texttt{getMass(3, tag)}), bounding box (\texttt{getBoundingBox()}), and boundary surface tags (\texttt{getBoundary()}).
    \item Detect edges: two bodies share an edge if their surface tag sets intersect (physical contact).
\end{enumerate}

\subsection{Step 2: Geometry Enrichment with trimesh}

\begin{enumerate}
    \item Export each body as STL mesh via gmsh.
    \item Compute \textbf{exact surface area} using \texttt{trimesh.Trimesh.area}, replacing the bounding-box approximation ($2(dx \cdot dy + dy \cdot dz + dz \cdot dx)$) that was the single biggest accuracy flaw in the original 13-dimensional feature vector.
    \item Compute \textbf{Shape Diameter Function (SDF)} statistics via trimesh inward ray-casting: sample $N$ surface points, shoot a ray along the inward normal, record first-hit distance (local thickness), then aggregate to obtain SDF mean (average thickness) and SDF variance (shape complexity).
\end{enumerate}

\subsection{Step 3: Component Type Inference}

The SDF statistics and bounding-box ratios drive geometry-based component type classification into 8 classes:

\section{Model Architecture}

\subsection{AssemblyGNN --- 3-Layer GAT Encoder}

The encoder is a 3-layer Graph Attention Network with multi-head attention:

\begin{table}[H]
\centering
\caption{AssemblyGNN Architecture}
\begin{tabular}{c c c c c}
\toprule
\textbf{Layer} & \textbf{Input Dim} & \textbf{Output Dim} & \textbf{Heads} & \textbf{Notes} \\
\midrule
GAT Layer 1 & 22 (in\_dim) & $128 \times 8 = 1024$ & 8 & Edge features injected \\
GAT Layer 2 & 1024 & $128 \times 4 = 512$ & 4 & \\
GAT Layer 3 & 512 & 64 (out\_dim) & 1 & No concat (single head) \\
\bottomrule
\end{tabular}
\end{table}

Each GAT layer applies:
\begin{equation}
\mathbf{h}_i^{(l+1)} = \sigma\left(\sum_{j \in \mathcal{N}(i)} \alpha_{ij}^{(l)} \mathbf{W}^{(l)} \mathbf{h}_j^{(l)}\right)
\end{equation}

where $\alpha_{ij}$ are learnable attention coefficients computed via:
\begin{equation}
\alpha_{ij} = \frac{\exp\left(\text{LeakyReLU}\left(\mathbf{a}^T [\mathbf{W}\mathbf{h}_i \| \mathbf{W}\mathbf{h}_j]\right)\right)}{\sum_{k \in \mathcal{N}(i)} \exp\left(\text{LeakyReLU}\left(\mathbf{a}^T [\mathbf{W}\mathbf{h}_i \| \mathbf{W}\mathbf{h}_k]\right)\right)}
\end{equation}

Multi-head attention ($K$ heads) concatenates $K$ independent attention outputs:
\begin{equation}
\mathbf{h}_i^{(l+1)} = \Big\|_{k=1}^{K} \sigma\left(\sum_{j \in \mathcal{N}(i)} \alpha_{ij}^{k} \mathbf{W}^k \mathbf{h}_j\right)
\end{equation}

Each layer is followed by ELU activation, Batch Normalisation, and Dropout ($p = 0.2$).

\subsection{LinkPredictor --- MLP Task Head}

The Link Predictor scores candidate edges by concatenating the source and destination node embeddings and passing them through an MLP:

\begin{equation}
\text{score}(u, v) = \text{MLP}(\mathbf{z}_u \| \mathbf{z}_v) \in \mathbb{R}
\end{equation}

where $\mathbf{z}_u, \mathbf{z}_v \in \mathbb{R}^{64}$ are the GAT encoder outputs. The MLP architecture is:
\[
\text{Linear}(128 \to 64) \to \text{ReLU} \to \text{Dropout}(0.1) \to \text{Linear}(64 \to 1)
\]

This encourages the model to discriminate between genuinely connected and merely similar components.

\section{Complementary Analysis Modules}

\subsection{Assembly Completeness Model (AssemblyTemplateDB)}

The \texttt{AssemblyTemplateDB} learns the expected component-type composition of each assembly category:

\textbf{Build phase} (after each training run):
\begin{enumerate}
    \item Load processed graphs (\texttt{data.pt}) and their source paths (\texttt{sources.json}).
    \item Group graphs by top-level source folder (e.g., \texttt{Hinge\_assembly/}).
    \item For each category, compute the median count of each component type across all assemblies.
    \item Cache results to \texttt{assembly\_templates.json}.
\end{enumerate}

\textbf{Match scoring} at inference:
\begin{equation}
\text{score} = \frac{\sum_{t \in \text{types}} \min(\text{present}(t), \text{expected}(t))}{\max(\sum \text{present}, \sum \text{expected})}
\end{equation}

A 25\% bonus is applied when all present types fit within the template (no unexpected components).

\subsection{Open Surface Detection (Octree-based)}

Adapted from the Octree spatial partitioning concept in Borah \& Borah (2020):

\begin{table}[H]
\centering
\caption{Conceptual Mapping from PEE Watermarking to Open Surface Detection}
\begin{tabular}{l l l}
\toprule
\textbf{Concept} & \textbf{PEE Watermarking (2020)} & \textbf{This Project} \\
\midrule
Spatial partition & Octree of mesh vertices & Octree of free-surface centroids \\
Unit of analysis & Vertex block & Surface cluster \\
Per-block decision & Watermark valid / tampered & Surface mated / open joint \\
Localisation goal & Which region was modified? & Where is a component missing? \\
\bottomrule
\end{tabular}
\end{table}

The pipeline:
\begin{enumerate}
    \item After \texttt{fragment()}, identify free surfaces (belonging to only one body).
    \item Filter by area threshold: surface area $\geq 4\%$ of parent body's total SA.
    \item Insert candidate centroids into an Octree (max depth = 3, up to $8^3 = 512$ leaves).
    \item From each non-empty leaf, select the surface with highest area ratio as the representative open joint.
    \item Extract triangle mesh for 3D visualisation (with synthetic grid fallback).
\end{enumerate}

\section{Skills AI --- AIDA (Gemini-Powered Agent)}

The \texttt{AssemblySkillsAgent} loads a domain skills profile (\texttt{engineering\_3d\_assembly.yaml}) covering six skill areas: mechanical engineering, 3D modelling, assembly design, parts identification, GNN interpretation, and assembly sequencing.

At inference time, AIDA receives the GNN predictions, node degrees, and open surface analysis results, and produces a structured 4-section engineering explanation:
\begin{enumerate}
    \item Not Assembled / Not Properly Mated
    \item AI Predicted Missing Links
    \item Open Assembly Joints Detected
    \item Overall Recommendation
\end{enumerate}

\section{Workflow Diagram}

The end-to-end workflow is:

\begin{enumerate}
    \item \textbf{Data Preparation:} Collect STEP files $\rightarrow$ Apply quality filters (deduplication, zero-contact pre-filter, size limits) $\rightarrow$ Parse with gmsh $\rightarrow$ Build PyG dataset.
    \item \textbf{Training:} 5-fold CV $\rightarrow$ GAT + LinkPredictor training with BCE + hard negatives $\rightarrow$ Early stopping $\rightarrow$ Save best checkpoint $\rightarrow$ Build template DB.
    \item \textbf{Inference:} Upload STEP file $\rightarrow$ Parse graph $\rightarrow$ GNN link prediction + Template matching + Open surface detection $\rightarrow$ AIDA explanation $\rightarrow$ 3D visualisation.
\end{enumerate}

\subsection{Training Pipeline}

The training pipeline (\texttt{train.py}) follows these steps:

\begin{enumerate}
    \item \textbf{Dataset loading:} Scan \texttt{Source\_3d\_models/} for STEP files; apply size filters; parse with gmsh; build 22-dim node features and 6-dim edge features; cache as \texttt{data.pt} + \texttt{sources.json}.
    \item \textbf{Data splitting:} PyG \texttt{RandomLinkSplit} with \texttt{train\_ratio=0.70}, \texttt{val\_ratio=0.15}, \texttt{test\_ratio=0.15}, split by assembly ID to prevent data leakage.
    \item \textbf{5-fold cross-validation:} \texttt{KFold} from scikit-learn; each fold trains independently with early stopping; the best fold (by validation AUC) is saved as \texttt{best\_overall.pt}.
    \item \textbf{Loss computation:} BCE with logits on positive + negative edges, plus a 0.3-weighted hard negative term.
    \item \textbf{Optimisation:} Adam with \texttt{ReduceLROnPlateau} (factor=0.5, patience=8). Early stopping at patience=20 epochs without improvement.
    \item \textbf{Post-training:} Build \texttt{AssemblyTemplateDB} from the processed dataset and cache to JSON.
\end{enumerate}

\section{Evaluation Metrics}

\textbf{Phase 1 metrics} (link prediction):

\begin{itemize}
    \item \textbf{AUC-ROC} (Area Under the Receiver Operating Characteristic Curve): Measures the model's ability to discriminate between true positive edges (existing connections) and true negative edges (non-connections). AUC = 1.0 indicates perfect discrimination; 0.5 indicates random guessing.
    \item \textbf{Average Precision} (AP): The area under the Precision-Recall curve, which is particularly informative when the positive-to-negative edge ratio is imbalanced (as in assembly graphs where most node pairs are not connected). High AP indicates the model ranks true connections above false ones.
\end{itemize}

\textbf{Phase 2 metrics} (planned --- next-component ranking):
\begin{itemize}
    \item Hit@K, MRR (Mean Reciprocal Rank), NDCG@K (Normalised Discounted Cumulative Gain at K).
\end{itemize}

\textbf{Phase 1 targets:} AUC-ROC $\geq 0.85$, Average Precision $\geq 0.82$.

\subsection{Key Findings}

\textbf{1. Feature engineering progression:} The node feature vector evolved from 13 dimensions (R1--R6) to 16 (R7--R14), then 18 (R15), 21 (R16), and finally 22 dimensions (R17). The most impactful individual changes were:
\begin{itemize}
    \item Replacing the bounding-box surface area approximation with exact trimesh computation (R7--R8).
    \item Adding geometry-driven component type inference via SDF ray-casting (R7--R8).
    \item Introducing affine-invariant shape descriptors: elongation, flatness, aspect ratios, sphericity (R15).
    \item Adding hard negative sampling (R15), which improved mean AUC from 0.624 to 0.726.
\end{itemize}

\textbf{2. Data quality vs.\ quantity trade-off:}
\begin{itemize}
    \item R13 (807 graphs, diverse) had lower AUC (0.574) than R14 (270 curated graphs, 0.624), demonstrating that domain-focused training outperforms broad noisy data at this scale.
    \item R17 (1,760 graphs after EDA-driven cleanup) achieved comparable AUC (0.625) to R14 despite 6.5$\times$ more diverse assemblies, showing effective generalisation.
\end{itemize}

\section{Conclusion}

This project demonstrates the feasibility of using Graph Attention Networks for intelligent CAD assembly assistance. The key contributions are:

\begin{enumerate}
    \item \textbf{Geometry-only graph construction:} A robust pipeline that converts standard STEP files into 22-dimensional attributed assembly graphs using gmsh + OpenCASCADE + trimesh + SDF ray-casting, without requiring proprietary CAD APIs.

    \item \textbf{GNN-based missing component detection:} A 3-layer GAT encoder with Link Predictor that achieves a mean Average Precision of $0.878 \pm 0.005$ under 5-fold cross-validation on 1,760 real-world assembly graphs --- exceeding the Phase 1 AP target of 0.82.

    \item \textbf{Assembly Completeness Model:} A template-based system (\texttt{AssemblyTemplateDB}) that learns per-category component-type distributions and identifies missing component types in partial or single-component uploads.

    \item \textbf{Octree-based Open Surface Detection:} Adapting the spatial partitioning concept from Borah \& Borah (2020) to localise the precise mesh surfaces where missing components should be assembled, with interactive 3D visualisation of flagged joints.

    \item \textbf{AI-powered engineering explanation:} A Gemini-powered Skills AI agent (AIDA) that translates GNN predictions into structured, actionable engineering recommendations across six domain skill areas.

    \item \textbf{End-to-end deployment:} An interactive Streamlit application with dual-panel UI (6-section analysis panel + 3D viewer with colour-coded overlays), supporting the full workflow from STEP upload through inference to explanation.

    \item \textbf{Feature engineering evolution:} A systematic progression from 13 to 22 node features, with each addition validated through ablation. The most impactful changes were exact surface area (replacing bbox approximation), SDF-driven component typing, and affine-invariant shape descriptors.

    \item \textbf{Data quality methodology:} EDA-driven quality improvements including cross-category deduplication, zero-contact pre-filtering, and size-based graph filters, enabling a 6.5$\times$ scale-up while maintaining model stability.
\end{enumerate}

The mean AUC-ROC of $0.625 \pm 0.017$ falls below the Phase 1 target of 0.85, indicating that the current homogeneous GAT architecture has a performance ceiling on the link prediction task for diverse assembly graphs. This motivates the architectural improvements planned for Phase 2.

\section{Future Work}

Phase 2 (July -- September 2026) will focus on:

\begin{enumerate}
    \item \textbf{Next-component ranking:} Activate the \texttt{NodeRanker} (already implemented in \texttt{model.py}) for ranking candidate next components by cosine similarity with the partial-assembly context vector. Evaluation via Hit@K, MRR, and NDCG@K.

    \item \textbf{Heterogeneous GNN:} Replace the homogeneous GAT with a heterogeneous graph network that models different node types (body, fastener, bearing, shaft, plate, housing, gear) and edge types (coincident, concentric, parallel, tangent, fixed) with separate parameter sets. This should unlock the AUC ceiling by enabling type-aware message passing.

    \item \textbf{BPR ranking loss:} Replace BCE with Bayesian Personalised Ranking loss for the next-component ranking task, which directly optimises the ranking of correct next components above incorrect ones.

    \item \textbf{GNNExplainer integration:} Apply GNNExplainer (Ying et al., 2019) to identify which subgraph structures and node features drive each missing component prediction, providing interpretable explanations alongside AIDA's engineering commentary.

    \item \textbf{Additional node features:} Add $\log(1 + n_{\text{holes}})$ as a fastener-signal dimension (64.6\% coverage from JSON metadata), apply $\log$ transforms with $3\sigma$ clipping on volume and surface area, and incorporate joint-type one-hot edge features from assembly metadata.

    \item \textbf{Data augmentation:} Oversample under-represented assembly categories (Tools, Machine Design) to reduce the 80\% Mechanical Engineering dominance bias. Deduplicate contacts to part-pair level to fix 379 over-dense graphs with phantom multi-edges.
\end{enumerate}
