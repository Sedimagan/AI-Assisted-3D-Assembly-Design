Title & Abstract

Project Title

AI-Assisted 3D Assembly Design: Predicting Missing Components in CAD Assemblies using Graph Neural Networks

Business Problem

In manufacturing and product design, engineers must manually verify that CAD assemblies contain all required components — a process that is time-consuming, expertise-dependent, and error-prone. A missing bolt, bearing, or joint can halt production. This project builds an AI system that automatically detects missing components from a partial 3D assembly upload and explains what should be added and where.

Abstract

A Graph Attention Network (GAT) is trained on assembly graphs to detect missing components via link prediction. A Gemini-powered AIDA agent explains predictions in engineering language. An Assembly Completeness Model learns per-category distributions. An Octree open-surface detector (Borah & Borah 2020) highlights unmated joints on the 3D mesh. Implemented entirely in Python using PyTorch Geometric — no proprietary CAD API dependency.

Key Contributions

  • GNN-based link prediction for missing component detection in 3D assemblies
  • 22-dim node + 6-dim edge features — geometry-driven SDF, affine-invariant shape descriptors, hole counts, joint types
  • Assembly Completeness Model — template-based gap analysis per assembly category
  • Octree open surface detection — spatial localisation of unmated joints
  • AIDA — Gemini AI agent for engineering-language explanations
  • End-to-end Streamlit app — interactive 3D viewer with dual-panel analysis

Challenges & Counter Actions

Challenges Encountered & Counter Actions Taken

⚠
Dataset Parsability — 61 of 300 STEP files failed

gmsh/OpenCASCADE timeouts (19) and complex geometry errors (42) rejected valid-looking assemblies. Higher-node assemblies (>60 edges) disproportionately timed out.

→ Built filter_models.py with node/edge thresholds; curated Best_models_for_training to pre-screen files before training runs.
⚠
AUC Target Gap — Phase 1 target ≥ 0.85 not yet met

Best mean AUC achieved is 0.726 (R15). Subsequent feature additions (22+6-dim schema, R18) regressed AUC to 0.483 despite richer features — larger diverse corpus hurt signal quality.

→ Focused corpus on 3 high-quality categories (R22): AUC recovered to 0.626 with Val≈Test parity. AP target ≥ 0.82 was achieved at R15 (0.917).
⚠
Scale vs Quality Tradeoff — More data hurt performance

R17 (1,760 graphs via deduplication + pre-filter) scored 0.625 AUC — worse than R15's 0.726 with only 270 graphs. R18 (995 graphs) also underperformed R15.

→ Introduced quality curation gate: graphs must pass category relevance + edge density checks. R22 (239 graphs) outperformed R18 (995 graphs) on AUC.
⚠
Category Diversity Degraded Generalisation

R20's expansion to 38 categories dropped AP from 0.835 → 0.749 and AUC stagnated at 0.503. Assembly topology patterns differ too widely across unrelated domains for a shared link predictor.

→ R22 narrowed back to 3 mechanically related categories; parity restored. Phase 2 will use category-specific model heads.
△
Training Instability — Epoch timeouts during R22 folds

Some epochs in R22 Fold 1 took 1,024s (vs typical 4–9s) due to MPS device contention on Apple Silicon. Caused irregular convergence in early epochs.

→ Added device-fix logic (R19+); best-checkpoint gate (best_serving.pt) isolates production model from unstable runs.

New Learnings from Phase 1

💡
Data Quality > Data Quantity

239 curated graphs (R22) beat 995 graphs (R18) on AUC. Curation criteria — category focus, edge density, parse success — matter more than raw dataset size.

💡
Val≈Test Parity Signals True Generalisation

R22's Val AUC (0.625) ≈ Test AUC (0.626), Δ = 0.001 — the first run where this gap effectively closed. A stronger signal of calibration than raw AUC score.

💡
Category Domain Homogeneity is Critical

Assembly link prediction is domain-sensitive: a bolt–shaft joint has different topology than a PCB–enclosure joint. Mixing unrelated categories introduces noise a single GNN head cannot reconcile.

💡
AP Consistently High Despite AUC Gaps

Test AP stayed above 0.68 across all 23 runs and peaked at 0.917 (R15). The model consistently ranks positive edge pairs well — ranking quality is solid even when AUC lags.

💡
Serving Gate is Essential Infrastructure

best_serving.pt promotion gate (R19) prevented 4 regressions across 25 runs. Without it, production would have been overwritten by R20, R21, R23, or R24 — all below the incumbent.

Phase 2 Actions

  • Category-specific GAT heads to handle domain diversity without mixing
  • Larger model capacity (256-dim hidden) for AUC ≥ 0.85 target
  • Automated STEP repair pipeline to reduce the 61 parse failures
  • Expand to 5+ categories with per-category serving gates
