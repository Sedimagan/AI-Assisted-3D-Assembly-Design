Phase 2

What is the Node Ranker?

Phase 1 answers "are these two parts connected?" (link prediction). Node Ranker answers a different question: "given this partial assembly, what type of component is most likely missing next?"

Partial assembly graph
→
GAT encoder
(already trained, Phase 1)
→
Mean-pool → context vector
→
Node Ranker
cosine similarity
→
Ranked list of 8 candidate component types

Committed design (already written into the Phase 1 report)

  • Candidates: the 8 fixed component types — body, fastener, bearing, shaft, plate, housing, gear, other
  • Scoring: cosine similarity between context vector and candidate embeddings
  • Loss: BPR (Bayesian Personalized Ranking)
  • Metrics: Hit@K, MRR, NDCG@K (targets: Hit@5 ≥ 0.70, MRR ≥ 0.64)

Phase 2 — Design

Key design decisions

Reuse, don't retrain

  • Node Ranker trains only its own small projection layer
  • Phase 1's GAT encoder is loaded frozen — no risk to the tuned link-prediction model
  • Minutes, not the ~23 hours a full Phase 1 run takes

Training task

  • Remove one real node from a training graph
  • Encode the remaining partial graph → context vector
  • BPR: true component type should score higher than the other 7

Separate checkpoint

  • New file: node_ranker.pt
  • best_serving.pt (Phase 1) is never touched
  • Explicit dependency: re-run if Phase 1 is ever retrained
Discussion

Open risks & questions for your input

1. The encoder Node Ranker inherits is still weak (AUC ≈ 0.55)
Since prototypes and context vectors both come from this encoder, Node Ranker's ceiling is partly capped by Phase 1's own accuracy. Should we prioritize improving Phase 1 (e.g. the heterogeneous GNN also planned for Phase 2) before pushing Node Ranker further?
2. Hit@5 is a weak metric at only 8 candidate types
Random guessing already gets 62.5% Hit@5, so the ≥0.70 target is only ~7.5 points above chance. We're reporting Hit@1 / MRR / NDCG@5 alongside it and a majority-class baseline for honest comparison — is that framing acceptable for the review board?
3. Class imbalance in the training corpus
Some component types (e.g. body, fastener) likely dominate the 695-graph corpus. There's a real risk BPR training just learns the class prior rather than genuine context-awareness — we're checking this directly against a majority-baseline comparison.
