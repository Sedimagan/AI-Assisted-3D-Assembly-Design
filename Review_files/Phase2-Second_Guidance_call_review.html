Title & Abstract

Title & abstract

AI-Assisted 3D Assembly Design: Graph Neural Networks for Missing-Component Detection and Next-Component Ranking in CAD Assemblies

This project models CAD assemblies as graphs — components as nodes, mates/joints as edges — and applies Graph Attention Networks to reason about assembly structure. Phase 1 addressed missing-component detection via link prediction over STEP-derived geometry features, supported by a template-based frequency prior and an Octree-based open-surface localizer, and delivered through a Gemini-backed explanation agent and a Streamlit/FastAPI application. Phase 2 extends the encoder to a heterogeneous, relation-aware architecture (RGATConv + TypedLinear) that gives each component type and joint type its own parameters, and introduces a Node Ranker head that answers a forward-looking question — given a partial assembly, which component type is most likely to complete it next — evaluated via Hit@K, MRR, and NDCG@K. The work is evaluated on real-world STEP assemblies spanning multiple mechanical-engineering categories, with an explicit, honestly-reported target of AUC ≥ 0.85 for link prediction that remains an open research problem addressed through architecture and data-scale experiments discussed in this review.

Design approach — multi-signal voting, not a single rule

  • Washer / Nut (hole detection): convex-hull volume ratio and a central-axis ray probe must both agree a through-hole exists
  • Bolt vs. plain shaft (head detection): bounding-cylinder fill ratio + center-of-mass axial offset + B-Rep face count — 2 of 3 must agree
  • Everything else falls back to elongation / flatness ratios (Long Shaft, Short Shaft, Thick/Thin Plate), with Body as the honest catch-all
  • Built as a read-only audit script (audit_component_types.py) — thresholds calibrated before touching the production classifier in dataset.py

Hardware Constraints

What the M1 MacBook taught us this cycle

Non-preemptible parsing calls

  • gmsh/OpenCASCADE STEP parsing can't be interrupted mid-call
  • A 300s timeout can actually run 5,000s+ before the kill takes effect
  • Handled by quarantining slow files rather than fighting the OS

Unified memory + MPS contention

  • No CUDA — MPS is the only GPU backend, sharing one memory pool with the CPU
  • Running Node Ranker + Shape VAE training simultaneously pushed swap to 25.8 / 26.6 GB — both jobs stalled
  • Fix: run Phase 2 and Phase 3 sequentially, not in parallel, on this hardware

These constraints directly shape the next-step options on the following slide.

Next Steps

Two directions for discussion

Option A — Prune the corpus

  • Drop Gate Valve and Tool Post — highest timeout/error rates, smallest usable counts (21 and 8)
  • Keep Bench Vice, Pipe Vice, C-Clamps, Crane Hook — 143 cleaner, more consistent assemblies
  • Faster, more stable training cycles on M1 hardware

Option B — Scope to fasteners

  • Focus identification + shape generation on Nut / Bolt / Washer only
  • These 3 classes are the most abundant (~30% of all bodies) and the most consistent across every category
  • A smaller, more tractable generation target — sidesteps category-specific geometry entirely

Both options are framed around the same constraint: keep the training loop fast and stable on a single M1 MacBook with no dedicated GPU. Seeking your guidance on which direction to prioritize.
