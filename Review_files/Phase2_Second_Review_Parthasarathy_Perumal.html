2 · Title & Abstract

Title & abstract

AI-Assisted 3D Assembly Design: Graph Neural Networks for Missing-Component Detection, Next-Component Ranking, and Shape Generation in CAD Assemblies

This project models CAD assemblies as graphs — components as nodes, mates/joints as edges — and applies Graph Attention Networks to reason about assembly structure. Phase 1 addressed missing-component detection via link prediction over STEP-derived geometry features. Phase 2 extends the encoder to a heterogeneous, relation-aware architecture (RGATConv + TypedLinear) and introduces a Node Ranker head that answers a forward-looking question — given a partial assembly, which component type is most likely to complete it next. This review adds a third head, built ahead of its originally proposed Phase 3 schedule: a hybrid shape generator (part-bank retrieval + conditional voxel VAE) that produces an actual 3D mesh of the missing component, not just its predicted type and location. Along the way, the 8-class component taxonomy was redesigned and audited against real corpus statistics, the training corpus was manually curated and standardized to 193 usable assemblies across 7 categories, and the resulting encoder (R33) was re-evaluated with all three downstream heads retrained against it.

Detection → ranking → and now, this review, generation of the missing component's actual shape

4 · Taxonomy Redesign

Why the component taxonomy needed a redesign

The problem, in real numbers

Old taxonomy: body / fastener / bearing / shaft / plate / housing / gear / other. Across 3,480 parts extracted with the old classifier:

body 58.8%
fastener 26.3%
plate 14.8%
bearing 0.03%
shaft / housing / gear / other — 0%

4 of 8 classes effectively never used — the taxonomy didn't match what our assemblies actually contain.

The bug this caused in production

  • A single mislabeled bearing — 1 example in the whole corpus — polluted that category's expected-components template
  • Produced a spurious "1 bearing missing" report in the live Streamlit UI, for every assembly in that category
  • Not a modeling accuracy issue — a taxonomy-design issue that surfaced as a user-facing correctness bug
4 · Taxonomy Redesign

New 8-class taxonomy — multi-signal voting, now live

Design approach

  • New classes: Long Shaft, Short Shaft, Thick Plate, Thin Plate, Bolt, Washer, Nut, Body (honest catch-all)
  • Washer / Nut: convex-hull volume ratio + central-axis ray probe must both agree a through-hole exists
  • Bolt vs. plain shaft: bounding-cylinder fill ratio + COM axial offset + B-Rep face count — 2 of 3 must agree
  • Everything else: elongation / flatness ratios (Long/Short Shaft, Thick/Thin Plate)
  • Audited first as a read-only script (audit_component_types.py), thresholds calibrated before touching production — then promoted to be dataset.py's single source of truth, replacing duplicated logic in part_bank.py / app.py

8 · Phase 3 — Shape Generation

Design — hybrid retrieval + generative fallback

Frozen encoder context vector
64-dim, shared with Node Ranker
→
Conditioning vector
ctx(64) ‖ type_onehot(8) ‖ target_bbox(3) ‖ neighbor_scale(2) = 77-dim
→
HybridShapeGenerator
retrieve if fit_score ≥ τ(0.6), else generate
→
Mesh, placed at open-joint centroid

Path A — ShapeRetriever

  • Nearest-neighbour query over the part bank by comp_type (+ category), ranked by bbox-aspect-ratio fit to the target open-joint region
  • Zero training required — real, always-valid CAD geometry

Path B — ConditionalShapeVAE

  • 3D-CNN encoder/decoder over 32³ occupancy grids, latent dim 128, ~6.46M params
  • marching_cubes (skimage) converts the output occupancy grid back to a mesh
  • Trained leave-one-out (BCE + soft-Dice + KL loss), 90°-rotation augmentation

Retrieval was the key de-risking move — it needed zero training and delivered the first demoable milestone ("system proposes the missing part's shape"); the VAE upgrades unmatched cases from nothing to a generated shape.

9 · Engineering Along the Way

Bugs found and fixed this cycle

Template category-path bug

  • _category_from_path() assumed a fixed one-level nesting under Source_3d_models/
  • Collapsed all 193 assemblies / 7 categories into one bogus blended template
  • Fixed to walk past known container directories; a real Bench Vice upload went from 10.4% → 96.2% template-match confidence

Corpus filter leak

  • dataset.py's category filter matched on any path component
  • Silently pulled rejected/ and slow_or_unstable/ files back into training, since they mirror category names one level down
  • Fixed before it could quietly corrupt a training run

Multiprocessing timeout/deadlock

  • Unconditional p.join() after p.kill() could block minutes-to-tens-of-minutes when a child was stuck in an uninterruptible OpenCASCADE/gmsh call
  • Plus a separate queue-flush deadlock / false-timeout race in part_bank.py's worker
  • Fixed with bounded, wall-clock-deadline polling loops instead
10 · Verification

End-to-end verification, and closing an open question

Verified against a real assembly

  • 2 bolts programmatically removed from a real STEP file — system correctly detected "bolt × 2" and placed 2 correctly-shaped ghosts on the 2 largest open surfaces
  • Classification, template matching, and shape generation all confirmed producing new-taxonomy output end-to-end, with zero old-taxonomy categories remaining anywhere in the pipeline

Resolving the guidance-call open question

At the 1 Aug guidance call, we asked whether to prune the corpus (drop Gate Valve/Tool Post) or scope down to fasteners-only, to work around class imbalance and M1 memory/time limits.

  • The taxonomy redesign fixed the underlying imbalance directly — all 8 classes now get real, non-trivial usage (slide 9)
  • So neither pruning nor narrowing scope was needed — the full 7-category, 193-assembly corpus was kept

12 · Open Items

What's next

Near-term

  • GNNExplainer integration — still pending, carried over from the last review
  • Threshold re-tuning for the 39.5% of bodies the new taxonomy's voting rules flag as ambiguous
  • Keep pushing AUC/MRR via architecture and per-category data quality — R31's lesson stands: raw data volume alone doesn't move the needle, quality and design do

Hardware constraint to plan around

  • No CUDA on the M1 — MPS is the only GPU backend, sharing one unified memory pool with the CPU
  • Running Node Ranker + Shape VAE training simultaneously pushed swap to 25.8 / 26.6 GB and stalled both jobs
  • Fix in place: run Phase 2 and Phase 3 training sequentially, not in parallel — needs to stay a standing constraint for future retrain cycles
