1 · Title & Abstract

Title & abstract

AI-Assisted 3D Assembly Design: Graph Neural Networks for Missing-Component Detection, Next-Component Ranking, and Shape Generation in CAD Assemblies

This project models CAD assemblies as graphs — components as nodes, mates/joints as edges — and applies Graph Attention Networks to reason about assembly structure. Phase 1 addressed missing-component detection via link prediction over STEP-derived geometry features. Phase 2 extends the encoder to a heterogeneous, relation-aware architecture (RGATConv + TypedLinear) and introduces a Node Ranker head that answers a forward-looking question — given a partial assembly, which component type is most likely to complete it next. This review adds a third head, built ahead of its originally proposed Phase 3 schedule: a hybrid shape generator (part-bank retrieval + conditional voxel VAE) that produces an actual 3D mesh of the missing component, not just its predicted type and location. Along the way, the 8-class component taxonomy was redesigned and audited against real corpus statistics, the training corpus was manually curated and standardized to 193 usable assemblies across 7 categories, and the resulting encoder (R33) was re-evaluated with all three downstream heads retrained against it.

Detection → ranking → and now, this review, generation of the missing component's actual shape

Classification algorithm — multi-signal voting

  • Old: single-signal SDF/bbox thresholds per class (elongation ratio → shaft, flatness → plate, …)
  • New: 2-of-3 signal agreement — bolt head needs cylinder-fill + COM-offset + face-count to agree; washer/nut need convex-hull ratio and a central-axis ray probe to both confirm a through-hole
  • Thresholds calibrated by a read-only audit tool before becoming the live classifier

Promotion-gate override — a modeled exception

  • Default policy: promote to best_serving.pt only if mean AUC+AP beats the incumbent
  • New rule added: when the incumbent and the candidate encode different taxonomies, the AUC comparison is not valid — override is manual, and the override itself is logged, not silent

Shape generation dispatch rule

  • fit_score = bbox-aspect-ratio similarity between a part-bank candidate and the target open-joint region
  • fit_score ≥ 0.6 → retrieve real geometry (zero training, always-valid CAD); else → ConditionalShapeVAE generates a novel mesh from a 77-dim condition vector
3 · Contribution of the Candidate

What I personally designed, built, and fixed this cycle

Design & build

  • Diagnosed a UI symptom ("1 bearing missing" on every assembly in a category) back to its taxonomy-design root cause — not a modeling bug
  • Designed the new 8-class multi-signal-voting taxonomy and its audit tool (audit_component_types.py) — calibrated on real corpus statistics before touching production
  • Designed and implemented the entire Phase 3 hybrid shape generator (retrieval + VAE) — proposed by my guide as future work; I brought it forward and built it this cycle
  • Manually curated and standardized the 193-assembly / 7-category training corpus, including a full parsability audit against the real parsing pipeline (not just visual review)

Debugging & engineering judgment

  • Found and fixed 3 real production bugs through independent root-cause analysis: a template category-grouping bug, a corpus-filter data leak, and a multiprocessing deadlock/false-timeout race — the last confirmed via isolated empirical testing, not guesswork
  • Made and documented the judgment call to manually override the automatic promotion gate for R33, with the reasoning written down rather than left implicit
  • Diagnosed and fixed an MPS/Apple-Silicon memory leak across 4 escalating layers during the R33 retrain, verifying each fix with real workload testing before trusting it
  • Ran full end-to-end verification on a real STEP file (not just unit tests) before calling the migration done

What this means

  • All three phases now have a working, retrained, and cross-verified head sitting on the same current encoder
  • Node Ranker's Hit@1 previously sat below its majority-class baseline — that's now resolved
  • Both Phase 3 design targets (IoU ≥ 0.35, chamfer ≤ 0.08) are met, with the feature wired into the live Streamlit UI

Still open

  • Node Ranker MRR (0.5723) has not yet cleared its 0.64 target

  • 39.5% of bodies flagged ambiguous by the new taxonomy's voting rules — an honest signal for further calibration
