What is K-Fold Cross-Validation?

Problem with single split: One random train/val/test split can give misleadingly high or low scores depending on which graphs land in each set. R11's val AUC of 0.781 was partly a lucky split — not a real signal.

How K-Fold CV works here

  • Fixed test set (15%) — held out across all folds, never seen during training
  • Remaining 85% split into 5 equal folds using sklearn.KFold
  • Each fold: 4 parts train → 1 part val. Repeat 5×
  • Fresh model trained per fold — no leakage between folds
  • Best model across all folds saved as best_overall.pt
  • Final report: mean ± std over 5 fold test scores

Why it matters: Mean ± std over 5 folds is a far more trustworthy estimate than a single split. Low std = model is consistent; high std = data is heterogeneous.

Code changes (13 Jun)

  • dataset.py — new get_splits(dataset, cfg, fold_idx, n_folds)
  • train.py — outer fold loop; saves best_fold{n}.pt per fold
  • config.yaml — n_folds: 5 added under training section
  • scikit-learn 1.8.0 installed in venv
  • Outputs: cv_summary.json alongside test_metrics.json

Category Filter — Domain-Focused Training

Problem (R13): Training on all categories (807 graphs from 1,404 STEP files) included architecture, art, sci-fi, jewelry — geometry irrelevant to mechanical assembly prediction. Mean AUC dropped to 0.574.

Solution: Category filter in config.yaml

data:
  categories:
    - "Mechanical Engineering"
    - "Machine design"
    - "Automotive"
    - "Tools"

Setting categories: null scans all subfolders (original behaviour).

Result: 306 STEP → 270 graphs. Zero files skipped — all 4 engineering categories produce compact assemblies within the nodes ≤ 20 / edges ≤ 60 thresholds.

Dataset Size Filters & Skip Policy

Three automatic filters run before training. Each oversized assembly folder is moved to a quarantine subdirectory and logged in skipped_models_report.json.

Filter thresholds

FilterThresholdRationale
Node count> 20 bodies74% of Fusion360 pass; larger = slow gmsh
Edge count> 60 directed3× dataset mean of 20.7 avg contacts
Parse timeout> 120 sReduced from 300s — pathological files

Two-stage check order (efficient)

  • Node check before fragment() — fast: just load + sync
  • Edge check after fragment(), before trimesh+SDF — avoids expensive per-body computation on dense graphs

3D Model Gallery Analysis — What Did We Actually See?

Used a generated HTML gallery (assembly_gallery.html) to visually browse the Fusion360 dataset categories — thumbnails of every assembly group used in training.

Student Finding — What was observed

  • Many assemblies in the full dataset are architecturally or artistically complex — not mechanical assemblies
  • Categories like SCI-FI, Art, Jewelry, Toys contain geometry irrelevant to bolt/bracket/shaft prediction tasks
  • Even within engineering categories, some files represent complete machines (100+ parts) rather than sub-assembly units
  • Product Design category: a mix of consumer goods and mechanical parts — unpredictable signal
  • Assembly graphs with 2–8 nodes train well; graphs with 15–20 nodes at the threshold limit tend to produce noisy edge predictions

Conclusion: The Fusion360 Gallery dataset is a general-purpose 3D model collection — not purpose-built for mechanical assembly training. Quality filtering by category + size is essential, not optional.

Ideal training assembly profile

Bodies (nodes)2–10 per assembly

What works best: The 4 categories used in R14 (Mechanical Engineering, Machine design, Automotive, Tools) align closest to this profile — confirmed by 0 skips and stable CV scores.

Next Steps — Better Data Sources

The Fusion360 Gallery is too broad. Targeted STEP files from these sources will improve training quality.

★ Priority 1 GrabCAD Community Library

Hundreds of thousands of free STEP assemblies. Searchable by type. No API — manual download. Target 50–100 per assembly category.

  • grabcad.com/library?query=bolt+bracket+assembly&softwares=17
  • grabcad.com/library?query=shaft+bearing+housing
  • grabcad.com/library?query=hinge+assembly

Priority 2 NIST MBE Test Case Suite

High-quality STEP assemblies with GD&T/PMI annotations — bolt patterns, brackets, flanged shafts. Small (~30 files) but geometrically clean. Ideal for pipeline validation.

nist.gov → Systems Integration → MBE PMI Validation Testing

Priority 3 FreeCAD Community Library

STEP + FCStd assemblies: nuts+bolts, brackets, hinges. M1-safe — most are 2–10 parts, exactly our target range.

github.com/FreeCAD/FreeCAD-library

Priority 4 PARTcommunity Standard Parts

Free STEP downloads: ISO bolts, bearings, linear shafts, brackets. Perfect for augmenting Shaft+Bearing+Housing and Plate+Bolt categories with standardised geometry.

b2b.partcommunity.com

Other sources

  • Thingiverse — mostly STL; but mechanical assemblies often include STEP source. Good for box+lid, bracket types
  • GitHub search — "*.step" assembly bolt / "*.stp" shaft bearing
  • github.com/kanzure/digitizing-historical-mechanisms (mechanical linkages in STEP)

Download strategy: Filter by STEP format. Target assemblies with 2–10 bodies. Avoid single-part files (UUID pattern already filtered by pipeline). Aim for 200–300 new files per category.
