1. Overview & Comparison

This guide covers two methods for hosting the Streamlit app externally, each with secure Gemini API key management.

Feature Streamlit Community Cloud Google Cloud Run
Best for Project demos, quick sharing Production, private repos
Setup time ~5 minutes ~15–20 minutes
Cost Free (public repos) Pay-per-use (generous free tier)
Custom domain No (*.streamlit.app) Yes
Private repos Paid plan only Yes (free)
Resources 1 GB RAM, shared CPU Configurable (up to 32 GB RAM)
API key security Streamlit Secrets (TOML) Google Secret Manager or env vars
Auto-deploy on push Yes Yes (with Cloud Build trigger)

2. Prerequisites

  • A GitHub account with the project repository pushed
  • A Gemini API key from Google AI Studio
  • The trained model checkpoint (back_end/checkpoints/best_overall.pt) committed or uploaded to the repo for inference to work
  • For Cloud Run only: A Google Cloud project with billing enabled and the gcloud CLI installed
Note on model checkpoints: The .pt checkpoint files are gitignored by default. For cloud deployment, you need to either add best_overall.pt to the repo (remove it from .gitignore) or use Git LFS / a cloud storage bucket to serve it.

4. Option A — Streamlit Community Cloud Recommended Free

The fastest path to a live URL. Streamlit auto-detects requirements.txt and packages.txt, installs dependencies, and serves the app.

Step-by-Step Deployment

  1. Push your code to GitHub

    Make sure your repository is pushed and up to date. The repo can be public (free tier) or private (paid plan).

    git push origin ph1-third-review

  2. Go to Streamlit Community Cloud

    Visit share.streamlit.io and sign in with your GitHub account.

  3. Create a new app

    Click "New app" and fill in:

    • Repository: Sedimagan/AI-Assisted-3D-Assembly-Design
    • Branch: ph1-third-review (or main)
    • Main file path: front_end/app.py

  4. Configure secrets (API key)

    Before deploying, click "Advanced settings" and paste the following into the Secrets text area:

    TOML
# Gemini API configuration
GEMINI_API_KEY = "your_gemini_api_key_here"
GEMINI_MODEL = "gemini-2.5-flash"

# Optional overrides
SKILLS_TEMPERATURE = "0.3"
SKILLS_MAX_OUTPUT_TOKENS = "2048"

    You can also add or edit secrets after deployment via Settings → Secrets in the app dashboard.

  5. Deploy

    Click "Deploy!". Streamlit will:

    • Install system packages from packages.txt (xvfb, mesa)
    • Install Python packages from requirements.txt
    • Launch front_end/app.py

    Your app will be live at https://your-app-name.streamlit.app

How secrets work in code: The app reads st.secrets["GEMINI_API_KEY"] as a fallback when the environment variable is not set. This is handled automatically by the _get_secret() helper in back_end/skills_agent.py.

Troubleshooting

IssueSolution
App crashes on startup Check the logs in the Streamlit dashboard. Common cause: missing best_overall.pt checkpoint file.
AIDA explanation says "offline" Verify GEMINI_API_KEY is set correctly in Settings → Secrets.
gmsh import error Ensure packages.txt is at the repo root with libgl1-mesa-glx.
Memory limit exceeded Streamlit Cloud has 1 GB RAM. Large STEP files may fail. Consider Cloud Run for heavier workloads.

5. Option B — Google Cloud Run Production

A serverless container platform. Your app runs in a Docker container, scales to zero when idle (cost-efficient), and can handle larger models and heavier workloads.

Step-by-Step Deployment

  1. Install & authenticate Google Cloud CLI

    If not already installed, follow the official guide. Then:

    # Authenticate
gcloud auth login

# Set your project
gcloud config set project YOUR_PROJECT_ID

# Enable required APIs
gcloud services enable run.googleapis.com containerregistry.googleapis.com cloudbuild.googleapis.com

  2. Build the Docker image

    From the project root directory, submit the build to Cloud Build:

    gcloud builds submit --tag gcr.io/YOUR_PROJECT_ID/assembly-ai

    This uses the Dockerfile and .dockerignore already in the repo. The build runs in the cloud — no local Docker needed.

    Alternative — local Docker build: If you prefer building locally, run:
    docker build -t gcr.io/YOUR_PROJECT_ID/assembly-ai . && docker push gcr.io/YOUR_PROJECT_ID/assembly-ai

  3. Deploy to Cloud Run (quick method — env var)

    For a quick deployment, pass the API key as an environment variable:

    gcloud run deploy assembly-ai \
  --image gcr.io/YOUR_PROJECT_ID/assembly-ai \
  --platform managed \
  --region asia-south1 \
  --port 8501 \
  --memory 2Gi \
  --cpu 2 \
  --allow-unauthenticated \
  --set-env-vars GEMINI_API_KEY=your_api_key_here,GEMINI_MODEL=gemini-2.5-flash

    Your app will be live at the URL printed in the output.

  4. Deploy with Secret Manager (recommended for production)

    For better security, store the API key in Google Secret Manager:

    # Create the secret
echo -n "your_api_key_here" | \
  gcloud secrets create GEMINI_API_KEY --data-file=-

# Grant the Cloud Run service account access
gcloud secrets add-iam-policy-binding GEMINI_API_KEY \
  --member=serviceAccount:YOUR_PROJECT_NUMBER-compute@developer.gserviceaccount.com \
  --role=roles/secretmanager.secretAccessor

# Deploy with the secret mounted as an env var
gcloud run deploy assembly-ai \
  --image gcr.io/YOUR_PROJECT_ID/assembly-ai \
  --platform managed \
  --region asia-south1 \
  --port 8501 \
  --memory 2Gi \
  --cpu 2 \
  --allow-unauthenticated \
  --set-secrets GEMINI_API_KEY=GEMINI_API_KEY:latest \
  --set-env-vars GEMINI_MODEL=gemini-2.5-flash

  5. Set up auto-deploy on push (optional)

    Create a Cloud Build trigger so every push to GitHub automatically rebuilds and deploys:

    gcloud builds triggers create github \
  --repo-name=AI-Assisted-3D-Assembly-Design \
  --repo-owner=Sedimagan \
  --branch-pattern="^main$" \
  --build-config=cloudbuild.yaml

    This requires a cloudbuild.yaml in the repo root (see below).

    cloudbuild.yaml
# Build and deploy to Cloud Run
steps:
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'gcr.io/$PROJECT_ID/assembly-ai', '.']

  - name: 'gcr.io/cloud-builders/docker'
    args: ['push', 'gcr.io/$PROJECT_ID/assembly-ai']

  - name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
    args:
      - 'gcloud'
      - 'run'
      - 'deploy'
      - 'assembly-ai'
      - '--image=gcr.io/$PROJECT_ID/assembly-ai'
      - '--region=asia-south1'
      - '--port=8501'
      - '--allow-unauthenticated'

images:
  - 'gcr.io/$PROJECT_ID/assembly-ai'

Troubleshooting

IssueSolution
Container fails health check Increase --memory (try 4Gi). PyTorch + gmsh can use significant memory at startup.
Build times out Add --timeout=1200 to the gcloud builds submit command.
Permission denied on Secret Manager Ensure the compute service account has the secretmanager.secretAccessor role.
Cold start is slow Set --min-instances=1 to keep one instance warm (incurs always-on cost).

6. API Key Security Best Practices

Never commit API keys to git. The .env and .streamlit/secrets.toml files are already in .gitignore. If you accidentally commit a key, rotate it immediately in Google AI Studio.

How the app reads secrets (priority order)

The _get_secret() helper in back_end/skills_agent.py checks:

  1. Environment variable — os.getenv("GEMINI_API_KEY") (works everywhere: local, Docker, Cloud Run)
  2. Streamlit secrets — st.secrets["GEMINI_API_KEY"] (Streamlit Cloud dashboard or local .streamlit/secrets.toml)

Per-platform recommendation

EnvironmentWhere to storeHow it's loaded
Local development .env file (gitignored) python-dotenv loads into os.environ
Streamlit Cloud Settings → Secrets (TOML format) st.secrets dict
Cloud Run (quick) --set-env-vars flag os.getenv()
Cloud Run (production) Google Secret Manager --set-secrets mounts as env var

Additional security tips

  • Restrict your Gemini API key to only the Generative Language API in the Google Cloud Console → Credentials → API key restrictions
  • Set a daily quota limit on the API key to prevent unexpected charges
  • For Cloud Run, use IAM-based authentication (remove --allow-unauthenticated) if the app should not be publicly accessible
  • Rotate API keys periodically and after any suspected exposure

7. Important Notes

Training vs. Inference: Training the GNN model requires significant compute and should be done locally (or on a VM with GPU). The cloud-deployed app is designed for inference only — it loads the pre-trained best_overall.pt checkpoint and runs predictions on uploaded STEP files.

Platform-specific adaptations

  • Folder picker: The macOS native folder picker (osascript) is automatically disabled on Linux (cloud). Users on the hosted app use the file uploader only.
  • Display server: The app sets DISPLAY=:99 for PyVista off-screen rendering. On Streamlit Cloud, the xvfb package (declared in packages.txt) provides this.
  • File paths: The app uses relative paths from the project root, so it works regardless of the deployment directory.

Updating the deployed app

  • Streamlit Cloud: Push to the connected branch — the app auto-redeploys within a minute.
  • Cloud Run: Re-run the gcloud builds submit and gcloud run deploy commands, or use the Cloud Build trigger for auto-deploy.
